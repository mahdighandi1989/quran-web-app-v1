# Scheduled job: cadence claims and a run log without deploy churn

## 🎯 چالش / Challenge
یک کارِ زمان‌بندی‌شده (روتینِ عامل/cron) بیرون از ریپو تعریف شده بود. نامش، UI، مستندات و حتی ثابتِ «دورِ بعدی» در سرور
فرض کرده بودند «ساعتی» است، ولی cron ِ واقعی «هر ۳ ساعت» بود. نتیجه: شمارشِ معکوسِ غلط به کاربر، و هشدارِ «مدتی است
سر نزده» که زودتر از موعد روشن می‌شد. هم‌زمان، اجراهای «بی‌کار» (صفِ خالی) هیچ ردی نمی‌گذاشتند، پس نمی‌شد فهمید
روتین اصلاً اجرا شده یا خاموش است. ثبتِ هر اجرا با کامیت روی شاخه‌ای که خودکار دیپلو می‌شود، هر چند ساعت یک دیپلو ِ بی‌تغییر می‌ساخت.

## 💡 راه‌حل / Solution
1. **یک منبع برای زمان‌بندی:** cron ِ واقعی را یک جا (پیش‌فرضِ کد + یک env ِ اختیاری) بنویس و هر متنِ UI/مستند را از آن
   بگیر یا به آن ارجاع بده. «هر N» را هرگز در متن تکرار نکن مگر کنارِ خودِ cron.
2. **اندازه‌گیری به‌جای فرض:** دورِ بعدی را از ضربان‌های واقعی بساز؛ فقط تا وقتی ضربانی نیست، cron ِ پیکربندی‌شده را فرض کن.
   هر اجرا ممکن است چند ضربان بزند (یکی برای هر آیتم)؛ دوره را فقط از ضربان‌های نزدیکِ «دقیقهٔ معمولِ شروع» بسنج و
   فاصله‌های کوتاه (کمتر از ۳۰ دقیقه) را یک بازدید بگیر. آستانهٔ «کهنه» = چند برابرِ **همان دوره**، نه یک ساعتِ ثابت.
3. **هر اجرا یک سطر:** حتی اجرای خالی. «بی‌صدا برای کاربر» ≠ «بی‌ثبت».
4. **ثبت بی‌دیپلو:** کامیتی که فقط فایلِ لاگ را عوض می‌کند، با برچسبِ رد‌کردنِ دیپلو ِ پلتفرم (مثلاً `[skip render]`) یا
   با buildFilter ِ مسیرها push شود؛ و قبل از آن مطمئن شو کامیتِ کدی هم‌زمان در همان push نیست (برچسب دیپلو ِ آن را هم رد می‌کند).
5. لاگ‌کردن را با تست/بیلدِ کامل گره نزن؛ فقط دروازهٔ ارزانِ مستندات + بررسیِ «فقط همین فایل staged است».

## 🧪 نمونه کد (Anonymized)
```bash
git fetch origin main && git checkout main && git merge --ff-only origin/main
test -z "$(git log origin/main..HEAD)"                 # nothing else unpushed
echo "- $(date -u '+%F %H:%M') UTC · queue empty · ok" >> docs/RUNLOG.md
git add docs/RUNLOG.md
[ "$(git diff --cached --name-only)" = "docs/RUNLOG.md" ]
git commit -m "docs(runlog): run $(date -u '+%F %H:%M') — empty [skip render]"
git push origin HEAD:main || { git pull --rebase origin main && git push origin HEAD:main; }
```

## ⚠️ نکات حیاتی / Pitfalls
- نامِ نمایشیِ روتین (مثلاً «ساعتی») در پلتفرمِ زمان‌بندی جدا از ریپوست و با عوض‌کردنِ cron عوض نمی‌شود.
- آستانهٔ «کهنه»ی وابسته به یک دورهٔ فرضی، با دورهٔ واقعیِ بلندتر هشدارِ کاذب می‌دهد.
- برچسبِ skip روی کامیتِ آخرِ push اثر دارد؛ کامیتِ کد را هرگز با کامیتِ لاگِ برچسب‌دار یک‌جا push نکن.
- سرویسی که rootDir دارد برای فایل‌های بیرون از آن اصلاً دیپلو نمی‌شود؛ سرویسِ بی‌rootDir برای **هر** کامیت دیپلو می‌شود.

## 🔁 چطور در جای دیگر اعمال کنیم / How to Apply Elsewhere
- [ ] `grep` برای «hourly / هر ساعت / every N» در UI، مستند و ثابت‌های کد؛ با cron ِ واقعی مقایسه کن.
- [ ] پیش‌فرضِ زمان‌بندی را یک جا بگذار (+ env)، و تستی که پیش‌فرض و متنِ UI را قفل کند.
- [ ] به دستورِ روتین «آخرین قدم: یک سطر در RUNLOG برای هر اجرا» اضافه کن.
- [ ] مطمئن شو کامیتِ فقط‌لاگ دیپلو نمی‌سازد (برچسبِ skip یا buildFilter) و پس از اولین اجرا با API ِ پلتفرم بسنج.
