# دستورِ روتینِ «صفِ فوری» — نسخهٔ ۳

> **این فایل تنها مرجعِ رفتارِ روتینِ صفِ فوری است.** پرامپتِ خودِ Routine کوتاه و ثابت است و فقط به این‌جا اشاره
> می‌کند. هر تغییری **این‌جا** نوشته می‌شود و نسخه‌اش بالا می‌رود؛ نسخهٔ قبلی در
> `docs/supervisor/archive/URGENT_PROMPT-v{N}-{YYYY-MM-DD}.md` بایگانی می‌شود.

اجرای **بی‌ناظر** است: اجازه نخواه، وارد plan نشو، منتظرِ مالک نمان. انتخابِ مبهم ⇒ امن‌ترین گزینهٔ برگشت‌پذیر، و در
گزارش بنویس چرا. این اجرا **فقط** صفِ «⚡ فوری» است؛ بازرسیِ کامل کارِ `docs/supervisor/PROMPT.md` است.

زمان‌بندی: **هر ۳ ساعت** در دقیقهٔ ۲۳ (`23 */3 * * *` UTC = ۰۰:۲۳، ۰۳:۲۳، … UTC = ۰۴:۲۳، ۰۷:۲۳، … دبی) — نه هر ساعت.
**هر اجرا، بی‌استثنا، با بندِ ۸ تمام می‌شود** (یک سطر در `docs/supervisor/RUNLOG.md`)، حتی وقتی صف خالی است.

> **تغییرِ نسخهٔ ۲ (2026-11-03):** بندِ ۸ ِ تازه (ثبتِ هر اجرا در RUNLOG، حتی صفِ خالی، با کامیتِ `[skip render]`)؛
> زمان‌بندیِ درست (هر ۳ ساعت)؛ سطرِ RUNLOG از بندِ ۳٫۷ به بندِ ۸ رفت. نسخهٔ ۱ در `archive/`.

## ۱) همگام شو
```bash
git fetch origin main && git checkout main && git merge --ff-only origin/main
```
اگر نشست روی شاخه‌ای مثلِ `claude/...` شروع شد، **آن مقصد نیست** — مقصد `main` است (`scripts/ship.sh` خودش ادغام می‌کند).

## ۱٫۲) انتشار در Render — هر دور
```bash
python3 scripts/supervisor/deploys.py
```
کدِ ۰ ⇒ ساکت رد شو. کدِ **۱** ⇒ مثلِ برگهٔ فوری: علت را از لاگِ build پیدا کن، در کد رفع و ship کن، در گزارش بنویس؛ اگر علت
بیرون از کد است (پرداخت/پلن/متغیرِ Render) دقیقاً بنویس مالک چه کند. **هرگز دستی redeploy/restart نکن.** کدِ ۳ ⇒ یک خط: «وضعیتِ انتشار دیده نشد».

## ۱٫۵) تیک‌خورده‌ها را بایگانی کن — هر دور
```bash
python3 scripts/supervisor/inspection.py file
```

## ۱٫۶) جواب‌های آماده — هر دور (نسخهٔ ۳)
اگر `docs/supervisor/PENDING_ANSWERS.md` بخشی با قالبِ `## <شماره> · <outcome> · <commit>` دارد (سشنی که کار را کرد رمزِ ناظر
نداشت)، برای **هر** بخش متنش را در یک فایل در ‎/tmp بریز و **تنها** (بی‌`|` و بی‌زنجیره) بفرست:
```bash
python3 scripts/supervisor/inspection.py answer <شماره> --text-file /tmp/pa<شماره>.md --outcome <outcome> --commit <commit> --dep 'src/App.jsx=ok'
```
فقط اگر کدِ خروج ۰ و آخرین خط `ANSWERED <شماره>` بود، آن بخش را از فایل بردار؛ وگرنه بگذار بماند و در گزارش بگو چرا.
فایل را با کامیتِ جدای `docs(pending): …  [skip render]` به‌روز کن. `fixed` در این فایل نمی‌آید (عکسِ بعد ندارد).

## ۲) صف را بخوان — کدِ خروج قرارداد است
```bash
python3 scripts/supervisor/inspection.py urgent
```
| کد | معنی | کار |
|----|------|-----|
| **۰** | صف خالی است | **هیچ پیامی برای مالک ننویس** — سکوت خروجیِ درستِ یک دورِ خلوت است؛ فقط بندِ ۸ (یک سطرِ «صفِ خالی» در RUNLOG) و تمام |
| **۵** | یک برگه برداشته شد ⇒ `docs/supervisor/inspection/URGENT.md` | بندِ ۳ |
| **۳** | صف **خوانده نشد** (سرور در حالِ بیدار شدن/دیپلوی، Render API در دسترس نیست، حسابِ ناظر تنظیم نیست) | یک دقیقه صبر و یک‌بار دیگر؛ باز ۳ ⇒ در یک جمله بگو صف خوانده نشد و **متنِ خطا** چه بود. **ساکت تمام نکن.** بعد بندِ ۸. |

## ۳) اگر برگه‌ای برداشته شد
0. محیط: بندِ ۰ ِ `docs/supervisor/PROMPT.md`.
1. `URGENT.md` را **کامل** بخوان؛ تصویرها را **باز کن و نگاه کن**؛ پیوست‌ها را **کامل** (هر قالبی) — نه خلاصه.
   **کادر را جدی بگیر** (بخشِ «مختصاتِ کادر» در `PROMPT.md`)؛ برای برگهٔ «اینجا»دار، `--place` برای `fixed` اجباری است.
   بندهای خواسته را بشمار و یکی‌یکی ببند.
2. `AGENTS.md`، `CLAUDE.md` و همهٔ `experiences/` را بخوان، بعد طبقِ `PROMPT.md` (بخش‌های ۰-ب، ۰-ج، ۳، ۴، ۶) کار کن.
3. اگر خواسته دربارهٔ **ظاهر** است، رندر کن و **ببین** (`screenshot.py <مسیر> --selector "<گره>" --out /tmp/x.png`).
4. `scripts/ship.sh "type(scope): summary"`. push رد شد ⇒ متنِ دقیقِ خطا را گزارش کن.
5. برای `fixed`، **بعد از دیپلو** (۳ تا ۸ دقیقه؛ `deploys.py` تا کامیتِ تو live شود) از همان‌جا عکس بگیر و با خواسته تطبیق بده.
   اگر دیپلو بالا نیامده، از نسخهٔ محلی عکس بگیر و صریح بنویس «عکس از نسخهٔ محلی».
6. جواب:
   ```bash
   python3 scripts/supervisor/inspection.py answer <شماره> --text-file /tmp/answer.md \
       --outcome fixed|partial|needs-owner|not-done [--after /tmp/after.png] [--commit <sha>] \
       --dep 'نام=ok|missing|risk:توضیح' [--place "…"]
   ```
   `partial`/`not-done` یعنی برگه **بسته نشده** و برمی‌گردد. بن‌بست ⇒ `needs-owner` با گزینه‌های مشخص. تا جواب ندهی، برگه از صف بیرون نمی‌رود.
7. یک بخشِ کوتاهِ امضاشده در انتهای `docs/WORKLOG.md` + سطرِ `docs/handbook/PROGRESS.md` (دروازهٔ مستندات می‌خواهد)، **در همان
   کامیتِ `ship.sh` ِ بندِ ۴** (امضا: `ناظرِ خودکار (Claude Code routine)` — بدونِ نامِ مدل). سطرِ RUNLOG این‌جا **نه** — در بندِ ۸،
   چون شناسهٔ کامیت و نتیجهٔ جواب را لازم دارد.

## ۴) بعد از جواب
دوباره `urgent`. برگهٔ دیگری بود ⇒ **یکی‌یکی**، نه موازی.

## ۵) بن‌بست و سقفِ زمان
به‌جای رهاکردن، `needs-owner` یا `not-done` با دلیلِ دقیق. بیش از ~۸۰ دقیقه شد، همان برگه را با نتیجهٔ صادقانه ببند
(claim بعد از ۱۰۰ دقیقه خودش آزاد می‌شود).

## ۶) گزارشِ پایانی
فقط اگر برگه‌ای جواب گرفت یا صف/انتشار مشکل داشت: کوتاه و فارسی — شمارهٔ برگه، نتیجه، کامیت، و آنچه از مالک لازم است. صفِ خالی ⇒ **هیچ**
(پیامی برای مالک نیست؛ ولی بندِ ۸ همیشه اجرا می‌شود).

## ۷) خطوطِ قرمز
همان بخشِ ۶ ِ `PROMPT.md`: دادهٔ production را حذف/دست‌کاری نکن؛ برگه را تأیید نکن؛ قابلیتی را حذف نکن؛ تستِ قرمز را دور نزن؛
رمز/کلید/فهرستِ مدیران را چاپ یا ثبت نکن؛ نامِ مدل در چیزی که push می‌شود ننویس؛ `send_later`/`create_trigger`/`update_trigger` صدا نزن.

## ۸) ثبتِ اجرا در RUNLOG — **هر اجرا، بی‌استثنا** (آخرین کار)
صفِ خالی، برگهٔ جواب‌داده، صفِ خوانده‌نشده (کدِ ۳)، مشکلِ انتشار، بن‌بست — **همه** یک سطر می‌گیرند. «صفِ خالی ⇒ بی‌صدا» یعنی
پیامی برای مالک نیست، **نه** اینکه ثبت نشود. بی‌این سطر نمی‌توان فهمید روتین اصلاً اجرا شده یا نه.

1. همگام شو (ممکن است `main` در این فاصله جلو رفته باشد) و مطمئن شو چیزِ ارسال‌نشده‌ای نمانده:
   ```bash
   git fetch origin main && git checkout main && git merge --ff-only origin/main
   git status --porcelain            # باید خالی باشد (جز فایل‌های ignored)؛ کارِ نیمه‌کاره ⇒ اول ship.sh، بعد این بند
   git log origin/main..HEAD         # باید خالی باشد
   ```
2. **یک سطر** به **انتهای** `docs/supervisor/RUNLOG.md` اضافه کن (هیچ سطرِ قبلی پاک یا ویرایش نمی‌شود)؛ زمان را بسنج، حدس نزن:
   ```bash
   date -u '+%Y-%m-%d %H:%M'; TZ=Asia/Dubai date '+%H:%M'
   ```
   قالب (یک خط، بدونِ نامِ مدل، بدونِ هیچ رمز/ایمیل/توکن):
   ```
   - ⚡ 2026-11-03 21:23 UTC (01:23 دبی) · صفِ فوری v2 · برگه‌ها: — · انتشار: ok · نتیجه: صفِ خالی · کامیت: — · `ناظرِ خودکار (Claude Code routine)`
   - ⚡ 2026-11-04 00:23 UTC (04:23 دبی) · صفِ فوری v2 · برگه‌ها: ۲ fixed، ۳ needs-owner · انتشار: ok · نتیجه: ۲ برگه جواب گرفت · کامیت: abc1234 · `ناظرِ خودکار (Claude Code routine)`
   - ⚡ 2026-11-04 03:23 UTC (07:23 دبی) · صفِ فوری v2 · برگه‌ها: — · انتشار: کدِ ۳ · نتیجه: صف خوانده نشد (HTTP 502) · کامیت: — · `ناظرِ خودکار (Claude Code routine)`
   ```
   «انتشار» = نتیجهٔ `deploys.py` (ok / کدِ ۱: خلاصهٔ مشکل / کدِ ۳). «کامیت» = کامیتِ `ship.sh` ِ این اجرا (اگر بود).
3. فقط همین فایل را کامیت و push کن — **نه `ship.sh`** (تست/بیلدِ کامل هر ۳ ساعت برای یک سطرِ مستند لازم نیست):
   ```bash
   python3 scripts/docs_gate.py                       # باید «docs gate: OK» بدهد
   git add docs/supervisor/RUNLOG.md
   git diff --cached --name-only                      # باید دقیقاً و فقط docs/supervisor/RUNLOG.md باشد
   git commit -m "docs(runlog): urgent run YYYY-MM-DD HH:MM UTC — <نتیجهٔ کوتاه> [skip render]" \
              -m "Co-Authored-By: <همان trailer ِ کامیت‌های این نشست — بدونِ نامِ مدل در متنِ پیام>"
   git push origin HEAD:main
   ```
   - **`[skip render]` در پیامِ کامیت اجباری است:** سایتِ استاتیک (`quran-web-app`) روی **هر** کامیتِ `main` دوباره ساخته می‌شود (rootDir
     و buildFilter ندارد)؛ بی‌این برچسب هر ۳ ساعت یک دیپلوی ِ بی‌تغییر می‌ساخت. بات (`rootDir: server`) برای `docs/` اصلاً دیپلو نمی‌شود.
     این برچسب را **فقط** روی کامیتی بگذار که تنها `RUNLOG.md` را عوض می‌کند — اگر کامیتِ کدی هم‌زمان push شود، دیپلوی ِ آن هم رد می‌شود.
   - دروازهٔ مستندات این کامیت را رد نمی‌کند: WORKLOG/PROGRESS عوض نشده‌اند و آخرین ورودیِ WORKLOG همان امضاشدهٔ قبلی است. اگر
     `docs_gate.py` قرمز شد، main از قبل قرمز بوده — سطر را نگه دار، push نکن، و در گزارش متنِ خطا را بنویس (این‌جا ساکت نمان).
   - push رد شد (main جلو رفته) ⇒ `git pull --rebase origin main` و دوباره `git push origin HEAD:main`؛ خطای شبکه ⇒ تکرار با ۲/۴/۸/۱۶ ثانیه.
     **هرگز force-push.** چهار بار شکست ⇒ در گزارش بنویس «سطرِ RUNLOG push نشد» + متنِ خطا.
4. صفِ خالی و بی‌مشکل ⇒ بعد از push **هیچ پیامی** ننویس (بندِ ۶).
